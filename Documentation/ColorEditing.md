# 调色、构图、预设与成片导出

镜序使用 macOS Core Image 在本机完成基础调色。调整参数保存在图库，原文件不变；导出生成独立成片，取消时保留已完成的文件。当前功能不包含局部蒙版、曲线编辑器、HSL、LUT 或 AI 修图。

## 操作

也可以通过 [Codex 本机 MCP 连接](CodexColorControl.md) 操作当前照片或明确选中的批次。AI 与界面共用编辑会话、自动保存和撤销；批量与导出在 Codex 展示固定清单并确认后执行。

双击照片，点击「调色」。每次停止输入 300ms 或结束拖动后自动保存。切图、完成调色、关闭窗口和退出应用前会等待保存；失败时留在当前照片，可重试或放弃未保存的调整。

「原图对比」使用同一解码流程下的未调整结果，不使用相机嵌入预览作为对比真值。单项可重置，「恢复原图」清除效果但保留安全修订记录。撤销／重做在当前编辑会话内有效，一次拖动算一步；快捷键为 Command-Z 和 Shift-Command-Z；文本输入优先使用系统文本撤销。

网格和胶片栏显示已保存的调整。调色面板展示成片直方图，原片直方图和质量诊断继续基于原始照片。修改效果不会重算质量、改动评分、旗标、关键词或相册。

## 自动构图与手动裁剪

在单图工具栏点击「构图」。没有裁剪记录时自动推荐一次；已有裁剪时显示当前取景，点击「重新推荐」才会分析。画布显示方向校正后的完整照片和当前调色效果，九宫格内为保留范围，框外为遮罩。拖动画框移动取景，拖动四角调整大小。

默认保持原图比例；可选自由、1:1、3:2、4:3、16:9，以及对应的横竖方向。自由比例只用于手动裁剪。切换固定比例围绕当前裁剪中心调整并限制在照片内，不自动重新推荐。下方显示裁剪后的原生像素尺寸；像素取整会产生最多一个像素的比例误差。

「应用」把本次草稿作为一次编辑保存到图库；「取消」和构图时的 Esc 丢弃草稿；「重置裁剪」将草稿恢复为完整画面，应用后生效，保留调色。切图或关闭窗口丢弃未应用构图，并按原有规则等待已应用编辑保存。保存失败时保留内存编辑，通过调色面板重试或放弃。构图期间不能修改调色、导出、分享或通过 MCP 改动照片。

推荐使用 Apple Vision 的物体显著区域、全身人物矩形和人脸矩形，输入为最长边不超过 2,048px 的完整画面。检测只用于主体定位，不识别身份、不保存检测结果、不上传照片。合并检测到的区域并增加宽高各 10% 的边距，求出目标比例下能完整容纳主体的最小裁剪框。原图比例下至少保留 50% 面积；主动选择其他比例不受此限制。边距和面积是保守的工程默认值，不代表审美评分。

无可用主体，或原图比例下仍保留超过 95% 面积时，建议保留原构图；指定比例无法容纳主体时保留当前草稿并提示手动调整。推荐不会主动排除检测到的人物，背景路人会限制收紧取景；检测不到的人物和肢体不能保证受到保护，请检查最终画面。检测失败仍可手动裁剪，来源离线或身份变化则禁止应用。

主体所需的 10% 保护边距超出原图时，也停止自动收紧：原图比例下建议保留原图，其他比例提示无法容纳。该规则用于避免将贴边的局部显著区域误当完整主体；用户仍可手动取景。

裁剪存储在现有调整 JSON 中，坐标为方向校正后完整画面的左上角归一化矩形。「原图对比」和「恢复原图」同时涵盖调色与裁剪；撤销／重做涵盖完整编辑历史。预览、直方图、缩略图、比较、分享调色成片与导出使用同一裁剪链；照片信息中的原片尺寸不变。预设、复制参数及 MCP 调色参数修改保留目标照片裁剪。不包含批量构图、MCP 构图工具、自动拉直、透视校正或生成式补图，XMP 裁剪预设继续拒绝。

## 参数与渲染

| 参数 | 范围与行为 |
| --- | --- |
| 曝光 | −5…+5 EV |
| 对比度、高光、阴影、白色、黑色 | −100…+100；正值增加对比或提亮相应区域 |
| 饱和度、鲜艳度 | −100…+100 |
| RAW 白平衡 | 拍摄时，或 2,000…50,000 K／色调 −150…+150 |
| 普通图片白平衡 | 拍摄时，或相对色温／色调 −100…+100；不是还原相机绝对白平衡 |

RAW 通过 `CIRAWFilter` 从源数据解码，普通图片通过 ImageIO／Core Image 读取并应用方向信息。固定处理顺序为白平衡、曝光、明暗及对比度、鲜艳度及饱和度、裁剪、缩放及输出转换。中间格式为半浮点、线性扩展 sRGB；显示和导出为 sRGB。明暗使用五点 Core Image 曲线，对比度使用指数映射；它们不是 Adobe 算法。

调色拖动时最长边为 2,048px，停止后生成完整尺寸图像。看图画布以裁剪后的原生像素计算 100%，裁剪不放大原有像素；构图画布始终适应窗口。后台串行渲染，取消旧请求并隔离过期结果。缓存包含文件指纹、编辑修订和物理像素尺寸，普通与调色缩略图共用后台容量管理，缓存可重建。见 [缓存与后台任务](BackgroundWork.md)。

## 预设和批量应用

「预设与调色」可以保存、重命名、删除预设，或者使用已复制的参数。勾选明暗、白平衡、色彩组，先以首张所选照片试用，再应用。仅替换预设提供的参数，未提供字段维持原值。删除预设不改变已调色照片。

批量操作使用当前选择，不扩大到完整筛选范围。确认清单列出原路径、参数分组、已有调整数量和不适用原因，先备份 SQLite，再在单个事务内更新。遇到确认后文件、来源或修订变化时整批回滚。成功后的「撤销批量调色」同样核对修订并先备份；后续编辑使旧撤销清单失效时会停止，不覆盖新的调整。

网格的 ⌘／Shift 多选与「批量选择」勾选共用同一集合，调色、移动、成片导出和分享的目标保持一致；单图入口只针对正在查看的照片。详见 [多选与系统分享](PhotoSharing.md)。

## Lightroom XMP

导入不执行 Adobe 渲染过程。镜序按命名空间解析属性和元素，严格接收以下效果字段：

- `Exposure2012`、`Contrast2012`、`Highlights2012`、`Shadows2012`、`Whites2012`、`Blacks2012`、`Saturation`、`Vibrance`。
- `WhiteBalance=As Shot`；或者 `WhiteBalance=Custom` 加完整的 `Temperature` 与 `Tint`。自定义绝对色温仅适用于 RAW。

名称、分组、作者、版本等列明的非效果元数据可以读取；类型支持标记会限制适用照片。曲线、HSL、锐化、蒙版、相机配置、旧式曝光字段及未知效果字段，即使数值为零也拒绝，不提供「忽略后导入」。非法值、冲突值、不完整白平衡、DTD／实体或超过 2 MB 的文件也拒绝。首版读取 UTF-8 XMP。

预设保存前显示参数和试用结果。现有评分／标签 sidecar XMP 导出是独立功能；它不会写入调色参数，也不被当成调色预设。

## 导出与图库保护

导出支持 JPEG（92%）、PNG、16 位 TIFF，默认裁剪后原生尺寸、sRGB，文件名为「原名-调色」。JPEG 将透明部分合成到白色，PNG／TIFF 保留透明度。复制拍摄 EXIF、GPS、IPTC 及选定 TIFF 拍摄信息，更新方向、尺寸与色彩配置，移除旧缩略图、RAW 私有 MakerNote 和调色指令。

确认清单冻结源照片、调整修订和目标路径。写入在目标目录的临时文件中完成，核对文件和目录身份后，使用同卷原子且不覆盖的提交。重名跳过，取消停止后续项目，失败不发布半成品，不自动重新导入图库。

「分享调色成片」复用同一渲染与 JPEG 编码，先等待编辑保存，再冻结修订。默认原尺寸、保留 GPS，可选最长边 2,048 像素；文件生成在应用专属分享缓存，同名编号，用户再次点击系统分享按钮后才交付。它不改变上面的「导出成片」默认行为。

调色记录跟随照片 ID；归档、批量移动和撤销保留参数。删除照片索引会同时删除其调整，先前的数据库备份仍包含记录。合并重复来源时，唯一或相同调整可以保留，不同调整会阻止该组的合并。原文件变化后旧调整仍保存，但暂停应用；重新扫描后可明确选择备份并放弃旧调整。

外接卷重新挂载可能改变系统卷标识和文件标识。重新授权来源会同步卷与目录身份；增量扫描也检查文件标识，大小和修改时间相同仍会更新变化的身份，并保留照片 ID 和用户标注。旧清单和指纹不符的调整继续按上述规则拒绝应用。

当前结构通过独立应用标识与 schema 版本识别。0.4.1 可将完整 v4 旧图库备份后单向转换；不重建照片或标注记录，仅添加调色表。未知或不完整旧格式继续拒绝写入。见 [迁移说明](LegacyCatalogUpgrade.md)，不要删除真实图库来完成开发验收。

## 开发验证

完整检查使用 `zsh Scripts/build.sh check`；调色专项由 `JingXuChecks` 的主执行链调用，也可用构建好的可执行文件执行 `--color-checks`。

构图专项使用构建后的 `JingXuChecks --composition-checks`，并已接入完整回归入口。它覆盖几何、EXIF 方向、导出一致性及编辑生命周期；不以算法检查通过替代真实照片的人工观感验收。

`JingXuChecks --composition-review <样本目录> <新的仓库外输出目录>` 只读样本，在新的隔离图库中生成原图／建议对比、三种格式的裁剪成片与 `review.json`；检查原片哈希、导出尺寸和 PNG 像素一致性。人工评价字段留空，需另行复核，不把建议结果作为人工标签。

真实文件只读验证支持 `JingXuChecks --color-file <原片> <新的仓库外输出目录>`。验证创建独立数据库，渲染并导出 JPEG／16 位 TIFF，重新读取尺寸，核对原片 SHA-256；样本和输出不进入 Git。

界面验证必须显式设置 `JINGXU_UI_TEST_ROOT` 为新的绝对路径。该路径同时隔离数据库、备份、日志和缓存；只选临时照片目录不足以隔离图库。对沙盒测试包应通过系统选择器授权照片和导出目录，再验证滑块输入、焦点、连续切图、缩放、预设、保存失败和退出重开。

CLI 检查不等于沙盒 UI 或所有相机机型通过；实际验证结果由本次交付记录说明。
