# 调色、预设与成片导出

镜序使用 macOS Core Image 在本机完成基础调色。调整参数保存在图库，原文件不变；导出生成独立成片，取消时保留已完成的文件。当前功能不包含局部蒙版、曲线编辑器、HSL、LUT 或 AI 修图。

## 操作

也可以通过 [Codex 本机 MCP 连接](CodexColorControl.md) 操作当前照片或明确选中的批次。AI 与界面共用编辑会话、自动保存和撤销；批量与导出在 Codex 展示固定清单并确认后执行。

双击照片，点击「调色」。每次停止输入 300ms 或结束拖动后自动保存。切图、完成调色、关闭窗口和退出应用前会等待保存；失败时留在当前照片，可重试或放弃未保存的调整。

「原图对比」使用同一解码流程下的未调整结果，不使用相机嵌入预览作为对比真值。单项可重置，「恢复原图」清除效果但保留安全修订记录。撤销／重做在当前编辑会话内有效，一次拖动算一步；快捷键为 Option-Command-Z 和 Option-Shift-Command-Z。

网格和胶片栏显示已保存的调整。调色面板展示成片直方图，原片直方图和质量诊断继续基于原始照片。修改效果不会重算质量、改动评分、旗标、关键词或相册。

## 参数与渲染

| 参数 | 范围与行为 |
| --- | --- |
| 曝光 | −5…+5 EV |
| 对比度、高光、阴影、白色、黑色 | −100…+100；正值增加对比或提亮相应区域 |
| 饱和度、鲜艳度 | −100…+100 |
| RAW 白平衡 | 拍摄时，或 2,000…50,000 K／色调 −150…+150 |
| 普通图片白平衡 | 拍摄时，或相对色温／色调 −100…+100；不是还原相机绝对白平衡 |

RAW 通过 `CIRAWFilter` 从源数据解码，普通图片通过 ImageIO／Core Image 读取并应用方向信息。固定处理顺序为白平衡、曝光、明暗及对比度、鲜艳度及饱和度、输出转换。中间格式为半浮点、线性扩展 sRGB；显示和导出为 sRGB。明暗使用五点 Core Image 曲线，对比度使用指数映射；它们不是 Adobe 算法。

拖动时最长边为 2,048px，停止后生成完整尺寸图像。画布以原片像素计算 100%，预览分辨率变化不改变缩放和平移。后台串行渲染，取消旧请求并隔离过期结果。缓存包含文件指纹、调色修订和尺寸，缓存可重建。

## 预设和批量应用

「预设与调色」可以保存、重命名、删除预设，或者使用已复制的参数。勾选明暗、白平衡、色彩组，先以首张所选照片试用，再应用。仅替换预设提供的参数，未提供字段维持原值。删除预设不改变已调色照片。

批量操作使用当前选择，不扩大到完整筛选范围。确认清单列出原路径、参数分组、已有调整数量和不适用原因，先备份 SQLite，再在单个事务内更新。遇到确认后文件、来源或修订变化时整批回滚。成功后的「撤销批量调色」同样核对修订并先备份；后续编辑使旧撤销清单失效时会停止，不覆盖新的调整。

## Lightroom XMP

导入不执行 Adobe 渲染过程。镜序按命名空间解析属性和元素，严格接收以下效果字段：

- `Exposure2012`、`Contrast2012`、`Highlights2012`、`Shadows2012`、`Whites2012`、`Blacks2012`、`Saturation`、`Vibrance`。
- `WhiteBalance=As Shot`；或者 `WhiteBalance=Custom` 加完整的 `Temperature` 与 `Tint`。自定义绝对色温仅适用于 RAW。

名称、分组、作者、版本等列明的非效果元数据可以读取；类型支持标记会限制适用照片。曲线、HSL、锐化、蒙版、相机配置、旧式曝光字段及未知效果字段，即使数值为零也拒绝，不提供「忽略后导入」。非法值、冲突值、不完整白平衡、DTD／实体或超过 2 MB 的文件也拒绝。首版读取 UTF-8 XMP。

预设保存前显示参数和试用结果。现有评分／标签 sidecar XMP 导出是独立功能；它不会写入调色参数，也不被当成调色预设。

## 导出与图库保护

导出支持 JPEG（92%）、PNG、16 位 TIFF，默认原尺寸、sRGB，文件名为「原名-调色」。JPEG 将透明部分合成到白色，PNG／TIFF 保留透明度。复制拍摄 EXIF、GPS、IPTC 及选定 TIFF 拍摄信息，更新方向、尺寸与色彩配置，移除旧缩略图、RAW 私有 MakerNote 和调色指令。

确认清单冻结源照片、调整修订和目标路径。写入在目标目录的临时文件中完成，核对文件和目录身份后，使用同卷原子且不覆盖的提交。重名跳过，取消停止后续项目，失败不发布半成品，不自动重新导入图库。

调色记录跟随照片 ID；归档、批量移动和撤销保留参数。删除照片索引会同时删除其调整，先前的数据库备份仍包含记录。合并重复来源时，唯一或相同调整可以保留，不同调整会阻止该组的合并。原文件变化后旧调整仍保存，但暂停应用；重新扫描后可明确选择备份并放弃旧调整。

外接卷重新挂载可能改变系统卷标识和文件标识。重新授权来源会同步卷与目录身份；增量扫描也检查文件标识，大小和修改时间相同仍会更新变化的身份，并保留照片 ID 和用户标注。旧清单和指纹不符的调整继续按上述规则拒绝应用。

当前结构通过独立应用标识与 schema 版本识别。0.4.1 可将完整 v4 旧图库备份后单向转换；不重建照片或标注记录，仅添加调色表。未知或不完整旧格式继续拒绝写入。见 [迁移说明](LegacyCatalogUpgrade.md)，不要删除真实图库来完成开发验收。

## 开发验证

完整检查使用 `zsh Scripts/build.sh check`；调色专项由 `JingXuChecks` 的主执行链调用，也可用构建好的可执行文件执行 `--color-checks`。

真实文件只读验证支持 `JingXuChecks --color-file <原片> <新的仓库外输出目录>`。验证创建独立数据库，渲染并导出 JPEG／16 位 TIFF，重新读取尺寸，核对原片 SHA-256；样本和输出不进入 Git。

界面验证必须显式设置 `JINGXU_UI_TEST_ROOT` 为新的绝对路径。该路径同时隔离数据库、备份、日志和缓存；只选临时照片目录不足以隔离图库。对沙盒测试包应通过系统选择器授权照片和导出目录，再验证滑块输入、焦点、连续切图、缩放、预设、保存失败和退出重开。

CLI 检查不等于沙盒 UI 或所有相机机型通过；实际验证结果由本次交付记录说明。

### 本次验证记录（2026-09-10）

- macOS 26.6.2、Apple Silicon、Swift 6.3.3；`zsh Scripts/build.sh check` 与 `zsh Scripts/build.sh adhoc` 均通过：27 组 JingXuChecks、29 项发布脚本检查，以及 Debug／Release 构建、测试包签名和 DMG 校验。
- 编辑会话检查实际覆盖 300ms 自动保存、并发保存、一次拖动一次撤销、数字输入撤销／重做、保存失败保留草稿、重试与放弃、原图对比、快速切图与过期渲染隔离。
- 使用 [f-spot 公开 RAW 样本](https://github.com/f-spot/raw-samples) 中的 Sony A700 ARW，在独立图库完成 4,272 × 2,848 原尺寸 JPEG 和 16 位 TIFF 导出并重新解码，原片 SHA-256 不变。此结果只覆盖这一实际相机样本。
- 沙盒测试包已通过系统选择器授权测试目录，索引 RAW／JPEG，并打开 RAW 单图入口。读取调色面板时 `SkyComputerUseService` 反复崩溃，镜序进程仍运行；实际滑块焦点、连续切图、100% 交互、退出保存及系统选择器导出闭环尚未完成 UI 验收。Core 的相应检查不能替代这些界面验收。
- 未发布、未替换已安装应用，旧格式图库仍按前述规则拒绝写入。
