# 按拍摄日期直接归档

在工具栏菜单选择“按日期重新归档…”。扫描整个图库的照片，不受网格筛选或 2,000 项显示范围影响。在确认清单中检查旧、新路径及跳过原因，再选择“授权并移动”，逐一授权原来源目录。

照片移入各自来源下的 `年份/YYYY-MM-DD/`，保留来源和资源 ID、评分、旗标、标签、相册关系与分析审核。使用 EXIF DateTimeOriginal 原始日期，不转换为电脑时区，不用导入日期填补缺失日期。同目录同名 RAW/JPEG 优先采用 RAW 日期，明确关联的共享 XMP 和 image.ext.xmp 随组移动。视频不动；无法确认关联的组跳过。照片与 XMP 的纯分组规则和安全导入共用，日期选择及移动恢复机制仍由归档协调器处理。

移动使用 macOS `renamex_np(RENAME_EXCL)`，仅同文件系统且禁止覆盖；不使用复制后删除。重名整组追加序号，内容相同也不自动去重。重复/父子来源、符号链接、来源离线和无可靠日期的项目跳过。旧目录保留；其他软件持有的旧路径不会自动修复。

## 备份、取消和恢复

- 开始前创建 SQLite 在线备份；失败不移动。照片本身不会被复制备份，请自行保有独立照片备份。
- `Application Support/JingXu/archive.json` 保存最近任务清单、SHA-256、文件身份与组进度；历史任务清单保存在同目录的 `archive-任务ID.json`。不得手工删除未完成日志来解除锁定。
- 取消在组边界停止；组内失败尝试安全回退。回退冲突时保留原状，禁止扫描、清理和来源管理。
- 启动时只对可以完全验证已经移动到位的组补交数据库；其他状态等待“恢复未完成归档…”。该入口重新授权原来源后继续处理。
- “撤销最近一次归档…”在备份图库后反向移动。文件被修改或原位置占用时不覆盖，并报告冲突。此入口仅针对最近任务，不提供历史任务选择器。
- 不能仅恢复数据库备份来撤销照片移动；必须同时处理文件路径。评分、旗标等不会回退到备份时状态。

## 验证边界

自动化使用独立临时图库和可注入的日期读取/移动服务，覆盖配套文件、内容校验、标注保留、备份失败、部分失败回退、重启继续、2001 项范围、取消、提交前中断、文件替换和禁止覆盖。

本机已通过 `swift build`、`swift build -c release` 和 Release 模式完整 `JingXuChecks`（21 项）；新增检查还覆盖整组重名序号、两种 XMP、相册/标签/审核保留以及父子来源隔离。`git diff --check` 通过。当前工具链为 Command Line Tools，未执行 XCUITest。

真实 RAW 日期读取、沙盒授权、外接卷拔出/跨卷、系统级进程强杀以及完整交互需在打包应用中人工验收。当前不自动操作真实图库、替换应用或发布 GitHub；未完成这些人工验收前请先在独立测试来源试用。
