# 质量分析 v2

## 当前交付状态

v2 已接入新照片分析、检查器和手动重算。**新模糊报警默认关闭**：尚未完成人工标注与独立验证，不能声称误报率下降或达到检出目标。没有用旧算法输出充当真值。

本次只交付代码、测试、说明及本机私有抽样结果；不发布 GitHub、不更换已安装应用、不自动重算真实图库。未来发布必须使用新的测试版编号，不覆盖已有安装包。

## 输入和指标

- `DecodedPreview` 用 ImageIO 创建带 EXIF 方向的预览；`SRGBPixels` 统一转到 sRGB、反预乘 alpha。直方图与质量分析都排除全透明像素，其余像素等权统计。
- 最长边 512 / 1024 两个尺度，绝不放大小图。大尺度不足 1024 或小尺度短边不足 128 时不做可靠模糊判定。系统只提供较小 RAW 预览时也遵循此限制。
- 每个尺度 8×8 区块。先做 3×3 二项式高斯轻度降噪，再计算局部标准差、Sobel 梯度能量、Laplacian 方差；后两者按局部方差归一化。
- 5×5 有效像素邻域防止透明边界贡献虚假锐度。剔除透明覆盖过多、低对比度、极弱纹理、噪声占比过高的区块。
- 汇总有效区块较清晰的四分之一。两个尺度均有至少 6 个有效区块、梯度和二阶指标均弱、并且没有可靠清晰区块时，才形成内部模糊候选；候选也必须通过校准门禁才能成为警告。
- 分辨率／纹理不足、尺度或指标矛盾均为“无法可靠判断”，不是“质量正常”。清晰背景而主体失焦可能漏报；不判断主体合焦、审美或照片是否值得保留。

参数定义在 `QualityParameters`，当前为 `v2.0-unvalidated-1`。所有阈值是未校准起点，不是通用准确标准。配置摘要绑定验证证据；修改冻结参数会使既有证据失效。应用不自动读取本机校准文件。

原理参考：[Apple 定向缩略图选项](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform)、[Laplacian 与降噪](https://docs.opencv.org/4.x/d5/db5/tutorial_laplace_operator.html)。实现为 Swift，不依赖 OpenCV。

## 提示与人工审核

- 高亮 243–255、暗部 0–12、近白 253–255、近黑 0–2 的亮度占比仅作客观统计，标注“基于解码预览”，不声称 RAW 传感器曝光失败或细节不可恢复。
- 相似连拍是独立信息和蓝色叠片徽标，不进入质量问题。仍沿用相机、2 秒邻接时间、Vision 特征距离 0.35 的分组条件；不重做分组算法。Vision 失败单独记录，不丢弃已经完成的像素统计。
- 黄色徽标和“待审核建议”共用条件：算法 v2、`suspectedBlur`、包含 `blurry`、人工状态 `pending`。旧结果、曝光统计、连拍、已接受／忽略均不进入。
- `saveComputedAnalysis` 与 `saveQualityReview` 分离。提交计算结果时在事务中读取最新人工状态；重算不修改评分、旗标、关键词、相册关系。明确接受建议才在同一事务中将旗标设为淘汰。
- 检查器显示结论、理由、各尺度尺寸、局部指标与参数版本；不把指标显示为“准确率百分比”。已处理建议保留人工审核说明。

## 迁移与重算

迁移 `v4-quality-assessment` 新增状态、诊断 JSON、文件指纹、错误，以及逐项队列表；升级协调器保留 v1/v2/v3 编号，迁移前在线备份并检查完整性，失败停止打开图库。旧分析原样保留，标为旧版，不变成正常结果。

菜单“重新分析当前范围…”使用当前已应用的来源、相册、智能集合、搜索和筛选；“重新分析全部旧结果…”不受当前筛选影响。两者均只取照片 ID，不受网格分页限制。确认后固定去重 ID 清单，开始前在 `Backups/Analysis/` 创建在线 SQLite 快照并检查完整性、记录 SHA-256；备份失败不创建执行队列。此快照不是“升级恢复包”，不要直接交给升级恢复选择器。

逐项进度保存在 `backgroundJobs` / `qualityJobItems`，不在每张完成时重写整个 ID 列表。暂停保留已完成项目；取消只停止后续；重新启动将运行中任务标为暂停，用户点“继续”才续跑。计算已保存而进度未提交的中断最多重算该项，仍保留最新人工审核。失败项记录原因并继续；重试失败项可结束本批次后通过检查器或当前范围另建任务。

后台操作统一通过应用操作门互斥，与扫描、导入、来源管理、文件清理不重叠；开始前必须解决未完成删除日志。人工评分／旗标编辑仍可进行。继续任务前检查备份校验值及算法版本。文件读取前、解码后及事务写入前复核身份／大小／修改时间，不把离线、权限或解码失败写成正常；普通重扫发现文件改变只标记结果过期，不偷偷重算旧照片。

## 本机私有校准工作流

独立命令行工具只读打开 SQLite，不调用会迁移图库的 `CatalogStore`。输出目录必须在所有 Git 仓库之外。命令行无法解析应用书签时，只使用本机已有读取权限访问记录路径，并复核文件指纹；不修改应用授权或系统安全设置。

```bash
swift build -c release --product JingXuCalibration
.build/release/JingXuCalibration prepare \
  --catalog '/path/to/Catalog.sqlite' \
  --output '/path/outside-git/new-private-samples' --count 120
```

`prepare` 按旧分数三档、明暗统计、日期、格式分层取样；旧分数仅用于覆盖范围。已有连拍组和同相机 2 秒邻接拍摄通过连通分组隔离，整组约 2:1 分配至校准／验证集。清单、原文件路径、预览、指标及人工标签均只留本机。

打开 `review.html` 查看编号和原文件位置。页面不显示分数、指标或分区，避免诱导答案。**必须使用本机可解码的查看器在原图 100% 下判断，页面缩略图不能代替人工验收**。在 `labels.json` 为各 ID 添加 `label`：`usable`（可用）、`blurry`（明显模糊）、`uncertain`（不确定），并填写 `reviewedAt100Percent: true`。文件缺失或不能查看时不要虚构标签；先恢复可读来源，再重新生成抽样清单。

```bash
.build/release/JingXuCalibration calibrate --directory '/path/outside-git/new-private-samples'
.build/release/JingXuCalibration evaluate --directory '/path/outside-git/new-private-samples'
```

`calibrate` 只用 calibration 分区，从版本化参数网格选低误报约束下召回最高的配置，写一次 `frozen-parameters.json`。`evaluate` 才读取 validation 分区进行指标评估；已产生验证报告后禁止在同一目录重新选参或覆盖结果。清单摘要、校准标签摘要不匹配时拒绝混用。

最低数值门槛：校准和验证分别至少 20 张明确可用、10 张明显模糊；独立验证误报率 ≤5%、明显模糊召回 ≥60%。报告同时包含样本量、不确定／失败／无法判断数及按场景结果。分母包含已明确标注但解码失败的照片，不能靠丢弃失败样本提高召回。小样本不证明总体准确率；仍需人工检查代表性。合成样本仅用于回归，不替代真实验收。

生成的候选／验证配置不自动安装到应用；未标注、未达标或样本不足时报警保持关闭。若查看验证结果后继续优化，应另建独立验证集，不能反复调参迎合原验证集。
