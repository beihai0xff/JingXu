# 系统照片与 iCloud 相册

镜序通过 Apple PhotoKit 接入这台 Mac 的系统照片图库。侧栏「系统照片」首次请求照片读写权限；未授权仍可使用本地图库。镜序不要求 Apple 账户密码，不提供第三方 iCloud 接口，也不读取「照片」的私有数据库。同步取决于 macOS「照片」中的 iCloud 设置、账户、网络和系统状态。

## 浏览、上传和相册

系统照片每页 200 张，可跨页多选和单图导航，支持缩略图、适合窗口、100% 缩放与胶片栏。切换相册清空选择，同一相册翻页保留明确选择。系统图库变化会更新列表、相册和当前预览；编辑中的照片发生变化时保留草稿并停止提交。

在本地图库选择照片，从「文件 → 加入系统照片…」选择原片或调色 JPEG 和目标普通相册。准备过程先冻结来源与调色修订并生成工作副本，确认完整固定清单后提交。原片保持原格式，成片复用现有 92% JPEG、原生尺寸、sRGB 与拍摄元数据设置；来源文件始终保留。确认时重新核对授权、文件身份和调色版本。创建照片与加入相册在一次 PhotoKit 事务内完成。

普通相册支持新建、改名、删除、添加和移出成员。相册菜单与图库照片删除使用不同入口：

| 操作 | 结果 |
| --- | --- |
| 移出此相册 | 只移除成员关系，照片保留在图库和其他相册 |
| 删除相册 | 只删除相册，保留其照片和视频 |
| 从系统图库删除 | 删除确认清单内的照片；启用 iCloud 后影响其他设备，通过系统「最近删除」恢复 |
| 本地清理淘汰图片 | 仅处理本地来源文件，不包含系统照片 |

成功提示为“已加入／保存到系统照片，iCloud 同步由系统处理”。PhotoKit 返回成功仅表示系统已提交修改，不能当成云端同步完成。

## 单图调色

静态照片和系统能解码的 RAW 复用现有调色、构图、预设、直方图拖动与撤销流程。修改参数只自动保存本机草稿，切图、关闭窗口和退出等待草稿写入完成；失败保留内存调整并阻止离开。点击「保存到系统照片」才更新当前同一照片。

编辑使用 `PHContentEditingInput` 给出的底图，保存使用 `PHContentEditingOutput` 和镜序格式的 `PHAdjustmentData`，保留 Apple 原片。镜序可以重开自己的参数；遇到不支持的其他软件调整，以系统提供的当前成片继续处理，界面标为「本次编辑前」。重置只清除镜序的效果。已烘焙为普通图片的底图不启用 RAW 控件。

提交前重新请求编辑输入，核对资源 ID、内容指纹、调整版本、系统图库会话和编辑权限。照片被修改、删除、图库切换或权限撤销时停止提交，保留草稿；旧草稿需由用户明确放弃后才能基于新底图编辑。Live Photo 不回写静态调色，避免损坏动态资源。

## 分析与恢复

「分析所选…」先展示固定照片清单，再按需下载原始静态资源并串行分析。暂停后可以继续未完成项；已完成项不重复下载。失败项显示具体原因，历史结果与本次未完成状态分开显示。相似连拍只在当前批次内计算，人工审核单独保存，重算不会覆盖。原有阈值不变，新模糊报警仍关闭。

本机数据位于 `JingXuPaths.applicationSupport()` 解析的目录，沙盒环境通常在应用容器中：

- `SystemPhotos.sqlite`：草稿、分析、人工审核、固定任务和写入记录。不得当缓存删除。
- `SystemPhotosWorking/`：应用创建的原片及成片工作目录，正常结束随会话或任务释放。重启在取得图库锁后清理遗留工作目录，不触碰草稿或提交记录。
- 现有 `Catalog.sqlite`：继续负责本地文件；本功能不修改它的结构。

所有系统写入与现有文件操作互斥。提交前保存记录；创建照片的标识在 PhotoKit 变更块内写入本机。若应用中断、回读失败或本机记录无法落盘，保留“待核对”记录并阻止新的系统写入。用户在「照片」核对后可明确结束记录，此操作不会自动重试或撤销系统操作。不要用删除数据库解除待核对状态。

## 隔离验证与范围

完整验证入口为 `zsh Scripts/build.sh check`，系统照片专项已注册到 `JingXuChecks` 主执行链，也可运行构建出的 `JingXuChecks --system-photos-checks`。测试只使用临时数据库、生成素材及 `IsolatedPhotoLibraryClient`，覆盖超过 2,000 项选择、相册语义、来源替换、权限拒绝和撤销、下载失败、取消继续、磁盘写入失败、重复提交、外部编辑冲突、图库不可用和中断记录恢复。

界面验证必须设置独立的 `JINGXU_UI_TEST_ROOT`；此模式注入假图库，真实 PhotoKit 客户端在初始化系统框架前拒绝该模式。仅选一个临时照片目录无法隔离系统图库。可先使用构建出的 `JingXuChecks --sharing-ui-fixtures` 生成完整本地测试库，再以它返回的目录作为环境变量启动测试应用。

**真实系统图库和 iCloud 跨设备同步尚未验收。** 当前没有独立 macOS 测试用户及专用 Apple 测试账户，不能把假服务通过当作真实同步证据。后续应在打包应用中核对照片读写权限、同一照片编辑、Apple 原片保留、第三方编辑底图、RAW、相册删除语义、系统「最近删除」恢复及跨设备结果。此能力纳入 [0.8.0 测试预发布版](Release-0.8.0.md)，本轮不替换已安装应用。

首版面向静态照片和 RAW；Live Photo 只浏览静态画面、整理和静态质量分析。视频、共享相册、系统照片 MCP 扩展不在范围内。

### 本轮验证记录（2026-09-18）

实现基于当时核实的 `origin/main d14e227`（0.7.1），工作分支为 `codex/system-photos`。验证使用 Swift 6.4、已安装的 macOS 26.5 SDK，部署目标仍为 macOS 14；通过环境变量指定工具链和 SDK，没有改变项目构建参数或降低签名要求。

最终 `zsh Scripts/build.sh check` 已通过：全部 Debug／Release target、完整 Release 回归、29 项发布流水线检查及 `git diff --check`。新增专项实际覆盖 2,005 项跨页固定范围，且本地调色切图、原图对比、导出、删除、既有图库打开和 MCP 回归通过。可在本机同一工具链环境中复现：

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools \
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk \
zsh Scripts/build.sh check
```

隔离开发应用使用生成的 PNG 和假 PhotoKit 服务，已实际操作系统照片入口、网格多选、单图入口、所选分析固定清单，以及暂停后继续至 9/9 完成。该开发应用没有启用沙盒，不能作为照片权限或正式安装包的验收证据。

继续验收时已解除锁屏阻挡，实际操作了本地单张照片的「文件 → 加入系统照片…」、连接假图库、准备原片及确认固定清单；准备完成后格式和目标相册不可修改。点击确认提交后，界面自动化服务再次返回 `Sky Computer Use native pipe closed before response`，重置工具后仍无法连接。镜序进程仍运行；只读检查隔离数据库确认该次上传记录为 `completed`，包含一个新照片标识，测试来源文件仍保留。由于未能读取提交后的画面，成功提示与网格新增照片的界面验收仍未完成。

本次再次运行 Release 版 `JingXuChecks --system-photos-checks` 通过。相册操作和调色／裁剪／快捷键交互的原生界面验收仍受自动化连接故障阻挡；这些功能的 Core 路径由注入服务检查覆盖。测试进程和临时开发应用已清理，未访问真实系统图库。真实系统图库、真实 RAW 编辑及跨设备同步仍待专用测试环境验证。

实现依据：[Apple PhotoKit](https://developer.apple.com/documentation/photos/phphotolibrary)、[非破坏式编辑](https://developer.apple.com/documentation/photokit/editing-asset-content)、[相册操作](https://developer.apple.com/documentation/photokit/requesting-changes-to-the-photo-library)。
