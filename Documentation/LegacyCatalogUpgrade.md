# 旧图库单向升级（0.4.1）

本次根据用户明确的旧图库保留要求，允许一项受限迁移，作为仓库默认不新增兼容机制规则的任务特例。只接受完整且结构匹配的历史 v1—v4 迁移链（最后为 `v4-quality-assessment`，包括 0.2.6）；不是支持任意早期数据库。

打开时持有图库排他锁。先只读校验格式、表及字段签名、迁移链、完整性和外键；未知应用标识、较新版本、缺失字段、额外表及触发器均拒绝，不改名、不清空、不换图库目录。

在 `Backups/Upgrades/legacy-v4-UUID/` 用 SQLite 在线备份保存含已提交 WAL 的独立 `Catalog.sqlite`，复制删除和归档日志并记录 SHA-256 清单。任一备份、日志读取或同步失败均停止迁移。随后在单个 SQLite 事务中新增 `colorEdits`、`colorPresets` 并更新格式标识；提交前校验完整性及外键。旧表、资源 ID、来源、评分、旗标、标签、相册、分析、导入任务和历史迁移链均保留，不接触照片。

进程在提交前终止由 SQLite 回滚，提交后下次启动识别当前格式，不重复转换；失败保留备份及恢复界面。恢复时校验数据库和日志摘要，保全当前数据库及 WAL/SHM、删除和归档日志，并通过持久恢复意图处理重试。

备份只用于数据库升级恢复，不是照片移动的撤销。后续若已移动或删除照片，不应直接恢复旧数据库；先处理相应操作日志。旧应用回退需匹配的数据备份，不能只替换应用。

自动测试使用独立构造库验证 WAL、原始记录、日志、备份失败、恢复和未知格式拒绝。可通过 `JingXuChecks --verify-legacy-copy /独立目录/Catalog-copy.sqlite` 对在线备份副本逐表逐字段比较；副本及私有数据不得进入仓库。真实账户只在副本验证、备份及用户授权后安装，不能拿真实库测试失败恢复或文件操作。

本次验收：统一 adhoc 构建入口的 Debug／Release、29 项发布脚本测试及 30 组应用回归通过。经用户授权，先验证旧图库副本，再备份并安装本地 0.4.1；首次启动转换后，全部旧表逐字段一致，删除和归档日志解析后记录一致，完整性及外键检查通过，退出重开正常。未进行真实照片移动、删除或调色；未执行断电、磁盘故障、跨设备及完整 XCUITest。未发布 GitHub。
