# 用 Codex 操控镜序调色

镜序内置本机 MCP 服务，Codex 通过 Streamable HTTP 操作已经打开的镜序。原片保持不变，界面与 AI 使用同一编辑会话和渲染器。当前支持单张与当前明确选择的批量照片；不包含全图库后台处理、曲线、HSL、蒙版或生成式修图。

## 连接

1. 打开镜序与图库，在设置中启用「允许 AI 助手连接」。默认关闭，监听地址为 `http://127.0.0.1:52831/mcp`。
2. 点击「复制 Codex 连接配置」，粘贴到本机 `~/.codex/config.toml`，或在 Codex 的 MCP 设置中配置同一地址及 Authorization 请求头。配置包含密钥，不要粘贴到对话、提交到仓库或共享。
3. 重连 MCP 后确认出现 `jingxu` 工具。仓库中的 `.agents/skills/jingxu-color` 会被项目内 Codex 发现；在其他项目使用时，将这个目录复制到 `~/.agents/skills/jingxu-color`。
4. 在镜序选择照片，在 Codex 中说「用镜序把当前照片调得暖一些，保留自然肤色」等需求。

配置形状如下，占位符必须替换为镜序生成的真实密钥：

```toml
[mcp_servers.jingxu]
url = "http://127.0.0.1:52831/mcp"
http_headers = { Authorization = "Bearer <镜序生成的密钥>" }
tool_timeout_sec = 120
```

端口被占用时先关闭连接，再修改端口。重置连接密钥会使旧配置失效，需要重新复制配置并重连。关闭功能停止监听并取消本连接尚未完成的后台工作；已经成功导出的文件保留。仅支持同机连接，不监听局域网地址。

## 跨页与单图范围

网格中的显式批选可跨页，MCP 从固定 ID 异步读取完整照片摘要，不从当前页裁剪目标。进入单图或双图比较后，MCP 只操作当前照片／活动候选；退出恢复网格批选。页面切换不扩大选择；当前目标、选择成员、查询范围和来源身份变化会更新 token。批量预检、执行前版本校验和对话中的固定清单确认保持不变。

## 调色与确认

`get_context` 返回选择标识、每张所选照片的编辑版本、当前照片参数和范围。单张操作使用 `selectionToken`、`assetID`、`editVersion`；版本同时包含文件、来源、已保存修订和当前草稿身份。返回当前状态后，若用户切图、修改参数或重新扫描更新了文件身份，旧操作会被拒绝。普通图片使用相对色温；RAW 使用绝对色温，两者不可混用。

`get_preview` 返回不超过 2,048px 的 PNG 和 sRGB 直方图，基于实际 Core Image 渲染，不使用生成图或相机嵌入预览替代。单张参数立即同步镜序，等待保存成功后返回；一次提交是一整步撤销。失败时保留未保存草稿，由镜序的重试／放弃入口处理。

`prepare_batch` 和 `prepare_export` 只准备固定清单，返回 `jobID`。调用 `get_job` 取得清单后，在 Codex 中展示照片范围、参数、跳过项与导出目标，用户确认后用 `execute_plan` 执行。新导出目录必须先通过 `choose_export_directory` 弹出的系统选择器授权，传入路径字符串无法绕过授权。

执行返回任务标识。重复执行相同清单返回原任务，不能造成第二次应用；通过 `get_job` 查询 running、completed、failed、cancelled 状态及具体结果。批量更新前备份，任一修订／身份校验失败整批回滚；成片导出不覆盖重名文件。取消保留已完成导出。批量撤销同样生成清单并检查修订。

清单、任务和目录标识属于各自 MCP 连接，不跨连接共享。重新连接或应用重启后失效，不自动重放。当前每次启用服务最多 16 个 MCP 会话；连接空闲一小时失效，每个服务控制器最多保留 128 个任务和清单，达到上限后重连。

## 隐私与实现

调色和渲染在本机完成。启用 AI 连接后，用户选择的照片预览、文件名、参数和明确操作清单可进入 Codex 模型上下文；不能将此流程描述成完全离线 AI。预览不携带源照片的 EXIF／GPS；成片导出继续沿用镜序原有的元数据规则。

连接密钥通过 Security.framework 生成并保存在 Keychain。HTTP 仅绑定 IPv4 loopback，验证密钥、Host、Origin、请求大小和 MCP 会话。MCP 使用官方 Swift SDK 0.12.1，HTTP 编解码使用 SwiftNIO。应用保留 Sandbox，只增加入站网络权限。网络模块不直接打开数据库；应用持有唯一图库连接、授权和编辑会话。

## 开发验证

完整回归：`zsh Scripts/build.sh check`。新增检查已接入 JingXuChecks，也可以使用构建后的 `JingXuChecks --mcp-checks` 执行协议和业务专项检查。

实际应用验证需要新的仓库外 `JINGXU_UI_TEST_ROOT`，同时隔离图库、缓存、备份、连接偏好及 Keychain 服务名。沙盒包的测试根目录必须位于自身容器可写的独立子目录，不能直接指定无授权的系统临时目录。测试照片和导出目录仍通过系统选择器授权，验证 Codex 获取图片、调整同步、保存与撤销、批量确认、导出、关闭连接及退出。测试程序的本机 HTTP 检查不能替代沙盒 UI 验收。

构建后的 `JingXuChecks --mcp-file <样本路径> <新的仓库外输出目录>` 使用独立图库验证真实 JPEG／RAW 的预览、改参、撤销、重做、导出尺寸和原片哈希。不会写回样本。`--mcp-serve-file <样本路径>` 可供实际 Codex 客户端实连；需通过 `JINGXU_MCP_TEST_TOKEN` 提供独立随机测试密钥，固定监听 52832，最多运行十分钟，终端会输出提前停止文件的位置。这是检查程序的隔离入口，不是应用的控制方式。

### 本次验证记录（2026-09-11）

已完成本机隔离图库的自动回归与沙盒应用实连验收。测试使用两张 JPEG 和公开 Sony A700 ARW 样本；下列故障注入与原生界面步骤分别记录，不将 CLI 结果当作 UI 结果。

- 构建与打包：`zsh Scripts/build.sh check` 通过；最终 `adhoc` 打包再次执行完整流程，Debug／Release 全部构建成功，29 项发布脚本测试和 29 组应用回归通过。沙盒测试包通过签名完整性及 DMG 校验。没有安装、替换现有应用或发布版本。
- 单张与实际 Codex：Codex 连接沙盒应用并收到 2048 × 1366 的真实 RAW 图片，完成曝光、阴影、鲜艳度及 RAW 绝对白平衡调整，回读保存版本及无未保存草稿状态。JPEG 相对白平衡、自动保存、撤销和重做也通过。原生撤销后，携带旧版本的 MCP 请求被拒绝。
- 原生界面同步：从网格由 MCP 打开编辑器，照片画面、三张胶片栏及左右导航正常；快速切图后过期请求失败。活动编辑会话切图完成保存，返回 RAW 后保留已保存参数。修复了 MCP 打开编辑器时未初始化导航顺序的问题。
- 混合批量：原生界面明确选择一张 RAW 和两张 JPEG，批量应用与撤销均为三张，画面调色标识同步更新。清空再重选使旧清单失效；预设保存、回读和应用通过。
- 导出：通过系统目录选择器授权，三张混合照片成功导出。RAW 成片为 4272 × 2848，JPEG 为 64 × 64。JPEG、PNG、TIFF 实际成片均已生成；预览和成片沿用相同渲染器与参数。重复执行返回原任务，重名不覆盖，任意路径字符串无法取得授权。
- 取消与会话断开：首张提交后调用 `cancel_job`，余下两张停止，已写入文件保留；另一轮首张提交后通过 MCP HTTP DELETE 关闭会话，剩余工作停止、成片哈希保持不变，新会话无法读取旧任务。这里验证的是显式会话关闭，不将其等同于所有网络故障。
- 来源离线与恢复：只读 HFS+ 测试磁盘映像在线时准备三张批量清单，卸载后执行失败且三张修订均未变化。重新挂载后拒绝旧身份；用系统选择器重新授权并扫描，三张预览与 JPEG 导出恢复成功。修复了重新授权漏更新卷标识、增量扫描漏检查文件标识的问题，并补充了保留照片 ID／用户标注的回归检查。
- 目录与保存故障：授权后的导出目录被替换时，执行拒绝且零写入。自动检查注入数据库保存失败、备份失败和事务失败，验证保留草稿、重试、整批回滚和不覆盖新修订；并发请求互斥，关闭连接等待在途操作退出。预览方向、尺寸限制及 EXIF／GPS 移除也有自动检查。
- 连接安全与生命周期：默认关闭、开关停止监听、正常退出、应用重启后旧会话／清单失效、密钥重置后旧密钥失效均在沙盒包实测。无密钥／错误密钥返回 401，非法 Host／Origin 返回 403。真实端口占用显示明确错误，修改到 52833 后连接成功，再恢复默认端口。
- 数据完整性：测试原片及只读卷内副本哈希均保持不变；既有打包输出恢复为原字节。测试目录、数据库、预览、密钥与详细日志留在仓库外。

验收范围为本机 macOS、上述 JPEG／Sony A700 ARW 样本及只读磁盘映像；未进行跨 macOS 版本、其他相机 RAW 格式或实体外接盘硬件矩阵测试。包采用 ad-hoc 签名，未公证、未发布。辅助功能工具仍无法稳定解析包含调色面板的完整树；相关画面与导航通过可读取的原生预览窗口、快捷键、MCP 回读和实际成片核对完成。
